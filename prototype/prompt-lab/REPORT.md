# DeepSeek 教学 prompt 实测与修订

日期：2026-09-28。使用环境变量中的密钥直接请求官方 `https://api.deepseek.com/chat/completions`；请求和返回模型均为 `deepseek-flash`。保持 `thinking: disabled` 和 `max_tokens: 1400`，没有截断回复或在界面隐藏模型实际输出。

共进行45次直接模型调用，另通过实际网页后端验证3轮教学和1次图片识别。试教扮演未认真听课、零基础、希望从作业学会做题的中国大学生；输入包括题24、高数乘积求导、二元一次方程组，及“没懂”“还是绕”“这两个相等就独立吗”“要求完整证明”“故意答错”等反馈。原始JSON保存实际请求的system prompt、学生话语、模型回复、模型名、finish_reason、usage与时延；没有密钥。分支JSON中forkedFrom指明继承到哪一轮，统计调用数时不重复计算继承轮次。

## 旧版问题

`baseline.json`中第一条就输出两个条件概率分式。我说看不懂后，它把“必须变成普通概率”当作必经方法；我再次说不会，它又列出两个公式，让我自己代入。3次回复分别为182、192、184个原始字符（包含LaTeX标记）。问题不只在长度，还在新符号过多、重复发问、缺少解释。

## 修订过程

- V1：限定一个动作、简短表达、不会时示范。仍会先抛通用乘积求导公式。
- V2：禁止陌生字母模板、优先原题具体操作。仍会目标和变形一起讲，或要求机械抄答案。
- V3：明确首次入口、回答当前疑问、示范与检查的区别。题24开场变为一句目标解释；中段仍会重复整条题目条件。
- V4—V6：公式限制包含句内公式；连续不懂时换具体数字；比较已有等式时只写新的结果。纠正“题目给的”与“推出来的”的混淆。
- V7—V8：加入用户要求的自然表达、明确主语与指代、因果顺序、主次关系及好坏改写对照。不能为了短而变成含糊口令。
- V9—V10：优先低负担解法；完整证明保留必要数学依据，尤其不能把直观独立性解释当成省略全概率步骤的借口。
- 单独的开场规则：只在尚无老师回复时加入；具体疑问直接回答，明确要答案给答案，发题求辅导才先说题目目标。避免每轮都重新介绍目标。

## 实际回复

网页正式接入后的原始回复见 `web-integration.json`：

学生：概率论零基础，请教我题24。

模型：“这题要你证明：知道B发生或知道B不发生时，A发生的概率不变，所以A和B独立。这句话能理解吗？”

学生：明白了，竖线是什么意思？

模型：“\(P(A\mid B)\) 读作‘在B发生的条件下，A发生的概率’。竖线就是‘已知竖线后面的情况发生’的意思。”

学生：B发生时A的概率0.4，不发生时0.6，也算独立吧？

模型：“不算。独立要求这两种情况下A的概率一样，比如都是0.4。你这里的0.4和0.6不一样，所以B发生与否改变了A的概率。”

`guarded24-a.json`第7轮：

学生：“这两个相等，所以就独立吗”

模型：“这两个概率相等，说明不管B发生还是不发生，A的概率都一样。既然B的情况改变不了A的概率，那A和B就是独立的。”

`final-proof.json`在上述教学历史后整理完整证明，已补全全概率公式及独立性结论。`final-v10-a.json`在新对话中不先展示公式，并正确纠正0.4/0.6仍独立的错误说法。

## 接入与验证

- 正式规则：`../teaching-prompt.txt`；开场补充：`../teaching-opening.txt`。
- 网页后端使用 `../teaching-instructions.cjs`；iOS使用从同一文件生成的 `../../ios/StudentHelper/TeachingInstructions.swift`。同步脚本 `sync-prompt.cjs`，`--check`检查一致性。
- `verify-teaching.cjs`通过真实后端检查短开场、符号解释、错误判断纠正；`../verify-images.cjs`确认图片识别没有被开场约束干扰，真实模型读出测试图片“47 + 18 = ?”。
- iOS 0.4.1使用相同规则，系统开场补充只在老师尚未回复时加入。

## 已观察到的限制

这些是有限的真实试教样本，不是全面准确率评测。模型仍有随机性：偶尔会重述题目、出现抽象措辞；冷启动直接要求完整证明时，有些回复仍选择较长但正确的代数路线。没有宣称它已与示范教师完全一致，也没有用很低的输出上限截断推导来制造“简洁”。后续应按实际学生反馈继续调整，并加入更多学科样本。
