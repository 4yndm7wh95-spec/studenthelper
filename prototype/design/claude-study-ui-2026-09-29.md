## 0. 先说清三件事

**已验证的**（我在 Node 里跑了测试，见 `tests/`）：分段算法（含公式不被拆、原文一字不丢、成对结构不被拆）、节奏状态机（25 项断言：首气泡立即、20 字 = 10000ms、暂停/恢复、跳过、销毁、短等待不闪指示）、DOM 接线（12 项）、全部配色的 WCAG 对比度、第 24 题 5 组示例的逐气泡输出与数学正确性。

**对用户偏好的理解**：“喜欢 Claude 自带的审美”我理解为「温暖、克制、纸感、有人味」，不是照抄 Claude 的界面或品牌色。所以我没有用陶土橙，选了另一套完整的配色：**奶油纸 + 松绿墨 + 荧光笔黄**。

## 1. 设计结论

**方向：一本摊开的作业本，旁边坐着一位老师。**

- 灰蓝的“脏”来自三处：大面积冷灰底、淡蓝气泡叠在灰上、低对比的灰字。全部去掉。底色改暖奶油（`#FFFCF6`），侧栏是比它深半档的暖米（`#F6F0E2`），卡片是纯白。**层次只靠三样东西：纸色 / 白卡 / 1px 暖线**，不再用半透明灰叠色。
- **学生气泡 = 实心松绿 + 白字**（对比度 6.39）。这是全界面唯一的大面积彩色，谁在说话一眼可见。
- **老师气泡 = 白底 + 1px 暖线**，四种角色（见 §4）：普通说明、重点（荧光笔黄底）、提问（松绿 1.5px 描边）、公式卡（直角化圆角 + 左侧松绿内边线）。强弱靠**字号、字重、底色、形状**，不靠灰度。
- 圆角统一为“圆 + 一个 6px 尖角”：气泡 18px，卡片 16px，输入框/按钮 12px，弹层 14px，弹窗 20px，输入条 24px。
- 动效只做一件事：**淡入 + 向上 8px，420ms，慢出**。没有弹簧、没有缩放、没有回弹。按钮按下只变色，不缩放。
- 只做浅色。理由：这是学习工具，用户已明确要“干净”，深色是另一整套配色与对比度验收，本轮不做；iOS 已有 `.preferredColorScheme(.light)`，网页加 `color-scheme: light`（已在 CSS）。

### 3.2 侧栏（桌面）/ 抽屉（手机）

结构自上而下：品牌行（高 40，“一步”+3px 绿点；右侧“新对话”次要按钮 36）→ 普通对话行 → “课程”分组标题（右侧 28×28 加号）→ 课程行（圆点 8px + 名称 + 数量 + 常显“…”）→ 展开的会话行（左缩进 36）→ 底部“本机保存”（高 40，绿点）。

- 选中的会话：底 `--accent-soft`，字 `--accent-ink`，字重 600。**去掉旧版左侧竖条**（有底色就不需要，少一层噪音）。
- 选中的课程：字重 600，不加底色。
- “…”按钮：桌面 28×28（右侧内缩 2），**常显**，颜色 `--ink-3`；手机 44×44。
- 会话过多：超过 8 条只显示前 8 条 + “全部 N 条 ›”。点击它弹出 280 宽弹层，顶部是查找框（自动聚焦，实时过滤，无匹配显示“没有匹配的会话”），下方是完整列表。已在 `workspace.js` 的 `case 'sessions'` 实现。

### 3.3 对话页

**空聊天**：居中 120×96 线稿图（`--ink-3`，1.5 描边）+ 26/34 “把题目发来”。输入条正常显示，无快捷按钮。

**正常教学**：学生气泡靠右，老师气泡靠左，宽度均随内容变化（`width: fit-content`，见 §4）。题目纸 `.yb-paper`：`--paper-card` 底 + 1px 线，16 圆角，内边距 16/20，全宽，上方小字“题目”带 .06em 字间距。分割线“第 N 题”：两侧 1px 线，文字 13px `--ink-3`。

**多图**：学生气泡内边距 6，图片间距 6，图片圆角 12，最大高 340，点击放大。

**长公式**：公式卡 `overflow-x:auto`，卡内不换行，横向滚动，滚动条细（`scrollbar-width:thin`）。卡片本身仍在气泡最大宽内，不撑破布局。

**完整答案**：不是特殊界面——就是一条长回复，按同一套规则分成 8–12 个气泡，公式各自成卡。用户可用“跳过等待”（§5.4）。

**加载（网络等待）**：老师侧一个 32 高小气泡，内三点。发送后 **300ms 才淡入**（快速返回时看不到）。语义为“老师在想”，因为请求确实在进行。

**错误/停止/未完成**：老师侧一条 `min-height:44` 的条，圆角同老师气泡（尖角在左下），错误 = `--danger-soft` 底 + `--danger` 字，停止 = `--sunk` 底 + `--ink-2` 字；右侧 36（手机 44）的重试图标键，`aria-label="重新回复"`。文案只有：`已停止`、`回复超时，请重试`、`连接失败，请重试`，以及应用被杀后重开时的 `回复没有完成`。

**停止**：请求进行中，发送键变成“停止”（松绿圆 + 白色实心方块 16px）。点击立即中止请求，出现“已停止”条。回复已到达、正在分句等待时不再有“停止”，而是“跳过等待”。

**回到最新**：用户上滑后有新内容时，输入条上方 16px 处居中出现 40×40 白色圆键（下箭头，1px `--line-strong`，`--sh-2`），右上角 9px 松绿点表示有新内容。点击回到底部并隐藏。

**顶栏跳转“题目”**：当会话内有 ≥2 道题时，标题右侧出现“题目 ›”ghost 按钮，行为不变。

**输入条**（`.yb-composer`）：白底，1px `--line-strong`，圆角 24，`--sh-2`。左“添加图片”回形针（桌面 40，手机 44 圆形 ghost），中间文本，右侧发送键（40，手机 44，圆形）。

| 状态 | 表现 |
|---|---|
| 默认 | 边框 `--line-strong` |
| hover | 边框 `--line-hover` |
| 聚焦 | 边框 `--accent` + 3px `rgba(29,107,85,.16)` 光晕，160ms linear |
| 拖入文件 | 底 `--accent-soft`，边框 `--accent` |

## 4. 回复结构协议与分段算法

### 4.1 分工

- **模型**：输出自然文本，用**空行**分气泡，一个完整意思一段；公式独占一段（`\[…\]`）；句内公式 `\(…\)`；每条最多一处 `**粗体**`；不输出标签/JSON/HTML。这与现有 `teaching-prompt.txt` 一致。**只需在“输出规则”末尾加两句**（见 §6）。
- **前端**：`StudentMath.plan(text)` 把原文变成“气泡计划”。**原文一字不改**地保存、导出、发给模型；视觉拆分不产生新的 API 轮次。
- **降级**：模型不给空行/不带任何标记 → 算法按标点与意思自己切；没有粗体 → 没有“重点”；没有问号结尾 → 没有“提问”。**绝不靠猜意思去强调**。

### 4.2 权重与字数

| 字符 | 权重 |
|---|---|
| 汉字 | 1 |
| 英文字母/数字 | 0.5 |
| 标点、空白 | 0 |
| 行内公式 `\(…\)` | 2（整体，不拆） |
| 裸公式（如 `P(A|B)=P(A)`） | 3 |
| `**粗体**` | 里面文字按上面计，标记本身 0，整体不拆 |

常量：`TARGET=25`（目标）· `SOFT=30`（合并句子的上限）· `HARD=36`（单气泡权重硬上限）· `PAIR_MAX=44`（“如果…那么”成对结构允许的上限）· `MIN_PIECE=8`。

### 4.3 算法（`web/math-render.js` → `plan`）

```
1  规范化换行；把“粗体里含公式”的 **…** 去掉星号（公式不能被粗体包住）
2  按换行分行。空行 = 模型明确的气泡边界，永远尊重
3  一行里若整行只有一个公式 → 公式卡（行内公式与裸公式统一升为独立公式卡）
   一行里出现 \[…\]/$$…$$ → 公式前后各自成为独立气泡
4  文字行 → 句子：在 。！？；处切（其后的引号/括号一并带上）
5  把相邻句子累加到 ≤ SOFT(30) 成一个气泡；单句 ≤ HARD(36) 不再切
6  单句 > HARD：在 ，、：处得到子句，做**动态规划**最优切分：
     代价 = (块权重 − 25)² / 4  + 碎片(<8)重罚  + 非连接词处切开罚 60
     · 在“所以 因此 那么 则 再 然后 接着 但是…”之前切，代价最低
     · “如果…那么 / 因为…所以 / 先…再” 成对区间内不许切（区间 ≤ 44 时）
     · 小数点 1,000 3.5 中的逗号/点不是标点
7  没有任何标点的超长句：只在 Intl.Segmenter('zh') 的**词边界**切；
   环境不支持则宁可不切，也不硬切一个词
8  权重 < 6 的碎片并入上一个气泡（合并后 ≤ 36，且上一个不是问句）
9  角色：公式 → formula；首个文字气泡含 ** → lead；
   最后一个气泡是文字且以 ？/? 结尾 → ask；其余 explain
```

不变量（`tests/edge.cjs` 逐个检查，0 失败）：公式定界符成对、粗体成对、气泡不以标点开头、把所有气泡拼回去（去掉空白/逗号/定界符）与原文完全相同。

### 4.4 四种角色的排版

| 角色 | 触发 | 底 | 边 | 字 | 形状 | 内边距 |
|---|---|---|---|---|---|---|
| **说明** explain | 默认 | 白 | 1px `--line` | 16/26 400 `--ink` | 18 圆角，左下尖角 6 | 10/14 |
| **重点** lead | 首个文字气泡含粗体（每条最多 1 个） | `--marker` | 1px `--marker-edge` | 17/28 600 `--marker-ink` | 同上 | 11/16 |
| **提问** ask | 最后一个气泡以问号结尾（每条最多 1 个） | 白 | 1.5px `--accent` | 16/26 500 `--ink` | 同上 | 9.5/13.5（补偿边框） |
| **公式** formula | 独立公式 | 白 | 1px `--line` + 左侧 3px 松绿内边线 | KaTeX 1.15em | **12 圆角**（与气泡形状区分） | 12/18/12/21，最小高 52 |
| 行内粗体 | 任意气泡内 | 下半行 34% 高的荧光笔条 `#FFE58A`（lead 内不再加） | — | 650 | — | — |

- 最多**三层强弱**：重点（黄）> 提问（绿框）> 普通（白）；公式卡是另一类，不参与强弱。
- 重点/提问也**不只靠颜色**：重点更大更粗，提问有描边。
- 气泡：`width: fit-content`，`max-width` 见 §3.1，`min-height: 44`（公式 52）。短句短气泡，到最大宽才换行。
- 间距：同一条回复内 8px；不同消息之间 20px。

### 4.5 等待时长（气泡 *i* 显示后，等多久显示 *i+1*）

```
汉字数 = 去掉公式后的汉字个数
有汉字      → 汉字数 × 500ms              （不设上限、不设下限；20 字 = 10000ms）
无汉字      → clamp(符号数 × 250, 2000, 6000) ms
              符号数 = 去掉 \[ \] \( \) $ 与空白后的字符数，命令（如 \mid）计 1
最后一个气泡 → 0
```

“无汉字”规则只为了纯公式/纯英文气泡不至于“零字延迟导致全部一起出现”，不影响 ×500 的明确需求。

| 23 | 图片预览 | 点缩略图 | 同 #14；遮罩同步淡入；放大切换 | 240ms / **放大：无动画** | 0 | ease-out | — | — | — |
| 24 | 焦点环 | 键盘聚焦 | **无动画**，立即出现 | 0 | — | — | — | — | — |
| 25 | 滚动跟随 | 见 §5.5 | 每帧贴底 | 480ms 窗口 | — | — | — | — | 用户手动滚动即停 |

**明确不用动效**：按钮按下缩放、消息列表内其它元素、图标切换（网页）、放大图、焦点环、tab 切换时的内容位移、任何 hover 位移、加载骨架屏、Toast 之外的“成功”庆祝。

### 5.2 等待指示（形态定稿）

- 形态：**老师侧一个小气泡**，白底、1px `--line`、圆角 16/16/16/6、高 32、内边距 0/14，内含 3 个 **6×6 圆点**，间距 6，颜色 `--accent`。位于最后一个已显示气泡下方 8px，左对齐。
- 动画：3 点依次“亮起再暗下”，周期 1500ms，相位差 200ms，`opacity: .4 → 1 (30%) → .4 (60%) → .4 (100%)`，`ease-io`。**不缩放、不位移**。
- **网络等待与准备下一句用同一个符号**。理由：对用户来说都是“老师还有话”，两套符号是噪音。语义都真实：网络等待 = 请求确实在进行；准备下一句 = 客户端有意逐句放出。不写任何“正在思考/推理”字样，读屏标签分别为“正在回复”“正在准备下一句”。
- 计时：气泡 *i* 出现后 **420ms** 淡入指示（若该段等待 < 1000ms，则不显示，避免一闪）；下一气泡出现的同时指示折叠消失。
- Reduce Motion：指示静止，3 点均 `opacity .7`，出现/消失用 200ms 线性淡入淡出，无高度动画。

### 5.3 状态机

```
                 ┌──────────────── 提前发送 / 点“跳过等待” ────────────────┐
                 │                                                        ▼
 network_wait ──收到回复──▶ first_visible ──▶ paced_wait ──计时到──▶ next_visible ──▶ (还有下一个?)──是──▶ paced_wait
      │                                          ▲  │                                          │否
      │                                          │  └─ 切走/后台 → 暂停（记剩余ms）→ 回来 → 按剩余继续
      │                                          └──────────────────────────────────────────────┘          ▼
      └─ 停止 / 失败 / 超时 → 错误条                                                                   complete
```

| 事件 | 处理 | 落点 |
|---|---|---|
| 学生发送 | 立即出现学生气泡；若有分句等待中，先 **skip**（剩余气泡 200ms 一次性淡入），再发请求；输入不锁 | network_wait |
| 网络等待 | 300ms 后显示指示；发送键 = 停止 | network_wait |
| 收到回复 | 首气泡 **同帧**出现；网络指示同帧移除 | first_visible → paced_wait（≥2 个气泡）/ complete（1 个） |
| 计时到 | 下一气泡出现；指示同帧收起 | next_visible → paced_wait / complete |
| **提前发送**（输入非空点发送） | 剩余气泡一次性淡入 → 发送新消息。旧回复全文已存，不丢 | complete → network_wait |
| **跳过等待**（输入为空时发送键 = 双箭头） | 剩余气泡一次性淡入 | complete |
| 切会话 / 换页 / 删除会话 / 重新渲染 | `finishAll()`：**无动画**立即完整显示，取消全部计时；不会有气泡插入另一个会话 | complete |
| 读旧历史 / 重新打开 | 全部气泡立即完整显示，**不重放延迟**（`enter=false` 时从不 pace） | complete |
| 别的会话的回复在后台到达 | 只入库，不分句；用户打开时完整显示 | complete |
| 网页标签页进入后台 / 锁屏 | `visibilitychange` → 暂停计时，记剩余毫秒；回来按剩余继续 | 原状态 |
| iOS 进入后台 | WKWebView 的 JS 计时随系统暂停，回前台按剩余继续；若进程被杀，重开后历史全部完整显示（`pacedReplyID` 只在内存） | complete |
| 应用/页面重启 | 全部完整显示；若最后一条是学生消息且无回复，显示“回复没有完成”条 + 重试 | complete / 错误条 |
| 停止（仅 network_wait） | 中止请求，显示“已停止”条 + 重试 | 无回复 |
| 失败 / 超时（95s） | 错误条 + 重试；输入不锁 | 无回复 |
| 重试 | 移除错误条，回到 network_wait；不重复生成已有回复 | network_wait |
| Reduce Motion | 计时**不变**（是内容节奏，不是动效）；位移/高度动画去掉，仅 200ms 线性淡入；指示静止 | — |
| 长等待 | **不锁输入**；发送键在输入为空时变“跳过等待” | — |

**原文与复制/导出/模型上下文**：始终整段原文，与“已显示到哪个气泡”无关。后续气泡尚未显示时导出与发给模型的内容仍是完整回复。网页/iOS 文本选择只作用于已显示气泡（未显示的气泡在 DOM 中 `hidden`）。

**是否需要跳过等待入口**：**需要，且已定**——输入为空、回复分句中时，发送键变为“跳过等待”（双箭头，`--accent-soft` 底）。完整证明可能要等近一分钟，学生在复习旧回复时不该被节奏拖住。不新增额外按钮，不弹说明。

### 5.4 滚动规则

- **贴底判定**：`stick`。初始 `true`；只有当**用户手动滚动**（wheel / touch / 指针事件后 1200ms 内的 scroll 事件）使离底部 > 80px 时才置 `false`；回到 ≤ 80px 置 `true` 并移除“回到最新”。内容自己变高（气泡展开、公式渲染、图片载入）**不会**改变 `stick`。
- **跟随**：新气泡出现或指示出现时，若 `stick`，用 `requestAnimationFrame` 在 **480ms** 窗口内每帧 `scrollTop = scrollHeight − clientHeight`（指示 300ms）。这样滚动完全贴合气泡的生长曲线，不会“先滚到旧高度再被撑开”。Reduce Motion 下只在事件发生时贴底一次。
- **用户上滑**：`stick=false`，不再拉扯滚动；有新气泡到达时显示“回到最新”键（带松绿点）。等待指示不强制保持可见，用户点回到最新即可。
- **等待指示可见**：贴底时指示始终在视野内（它在列表最末）。
- **发送时**：学生发送强制 `stick=true` 并滚到底。
- **切会话/重渲染**：恢复上次 `scrollTop`，没有记录则贴底。
- **iOS**：`ScrollViewReader` + 底部锚点 `Color.clear.id("bottom")`。`stick` 只在用户下拉手势（`DragGesture` 下拉 > 6pt）时置 `false`，锚点出现时置 `true`。每个 `WKWebView` 通过 `mathHeight` 消息（`requestAnimationFrame` 合并）回报高度，SwiftUI 设置 `.frame(height:)` 且 `.transaction { $0.animation = nil }`（高度动画由网页里的 CSS 驱动，避免叠加）；`MathMessageBody.onGrow` 触发 `follow()`：贴底时不带动画 `scrollTo("bottom")`，否则显示“回到最新”。

### 5.5 关键实现（已写入实施文件）

`web/math-render.js` 里的 `createPacer(delays, hooks, env)` 是**纯逻辑**（不碰 DOM，定时器可注入），DOM 层 `pace()` 只是适配器：

```js
const pacer = createPacer(delays, {reveal(i,mode){…}, wait(on){…}, done(){…}});
pacer.start();  pacer.skip();  pacer.pause();  pacer.resume();  pacer.destroy();
```

`delays[i]` 来自 `plan()` 的 `ms`，写在每个气泡的 `data-ms` 上；`workspace.js` 与 iOS 的 `WebMath/index.html` 共用同一份。
